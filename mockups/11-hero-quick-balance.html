Implementation notes

What this reuses

  • Saving calls the existing AccountSvc.SetBalanceAsync once per changed account — same DTO, same adjustment transaction, no schema change. Untouched rows are skipped.
  • The toggle maps to the existing RecordAdjustment flag; adjustments already stay out of monthly income/spending, so the −$62.80 pill won't jump when you reconcile.
  • The sheet is the same sb-* bottom-sheet pattern as Accounts, promoted into a shared component both pages use.

Behaviour details

  • With a single account, the sheet is just one row — identical to today's Reconcile, one tap closer.
  • First row autofocuses with its value selected, so the common case ("my checking is actually $X") is tap → type → save.
  • Save button stays disabled until something actually changes.
